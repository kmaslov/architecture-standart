| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| **F**   | **Функциональные (Functionality)**     |              |
| F1  | Новый клиент может посмотреть на сайте список доступных депозитов | При этом отображаются только актуальные ставки |
| F2  | Новый клиент может подать заявку на депозит через сайт | Требуется указать Ф.И.О. и номер телефона |
| F3  | Заявка с сайта должна автоматически передаваться в систему кол-центра |  |
| F4  | Клиент может посмотреть в интернет-банке список доступных депозитов | При этом отображаются актуальные ставки и персонализированные ставки лично для него |
| F5  | Клиент может подать заявку на депозит через интернет-банк | Требуется указать счёт и сумму депозита |
| F6  | Заявка из интернет-банка должна подтверждаться кодом, который нужно отправлять клиенту в СМС |  |
| F7  | Заявка из интернет-банка должна автоматически передаваться в АБС для дальнейшей обработки менеджером бэк-офиса |  |
| F8  | Менеджеры депозитов и кредитов могут работать со ставками по депозитам в АБС |  |
| F9  | Менеджер депозитов может согласовать ставку по заявке в АБС |  |
| F10 | После подтверждения размера ставки и открытия депозита в АБС клиенту должно отправляться СМС-уведомление |  |
| **U** | **Удобство использования (Usability)** |              |
| U1  | Интерфейс должен соответствовать системе дизайна, принятой в компании | Пользователи должны видеть привычные цвета и брендированные элементы |
| U2  | Форма заявки должна быть простой и понятной | Минимум полей, понятные подсказки |
| **R**   | **Надёжность (Reliability)**           |              |
| R1  | Все сервисы должны работать 24/7 |              |
| R2  | Доступность сервисов должна составлять 99,9% времени |              |
| **P**   | **Производительность (Performance)**   |              |
| P1 | Отклик по всем операциям должен занимать не более 100 миллисекунд |              |
| P2 | Возможность горизонтального масштабирования всех компонентов |              |
| P3 | Возможность равномерного распределения запросов между серверами |              |
| **S**   | **Поддерживаемость (Supportability)**  |              |
| S1  | Нужно предусмотреть разработку документации для дальнейшего расширения системы |              |
| S2  | Необходим мониторинг состояния сервисов | Он должен включать оповещения о сбоях или снижении производительности |
| <strong>+R</strong>  | **+Ограничения (Restrictions)**       |              |
| +R1 | Следует по возможности избегать привлечения подрядчика для доработок ядра системы | Функционал работы с СМС можно реализовать силами команды разработки банка |
| +R2 | Требуется шифрование трафика на сайте и в интернет-банке |              |
| +R3 | АБС может масштабироваться только вертикально из-за своей базы данных |              |
| +R4 | Нужно как можно больше использовать технологии, которые уже есть в банке | Например, базы данных MS SQL и Oracle |
| +R5 | Можно развернуть новые технологии, но необходимо, чтобы они были совместимы с существующими платформами разработки | Желательно, чтобы внутри банка уже была экспертиза — сотрудники понимали новые технологии хотя бы на уровне языков программирования |
| +R6 | Если нужны очереди сообщений, то лучше использовать Kafka |  |
| +R7 | Текущая версия платформы интернет-банка несовместима с Kafka | |
